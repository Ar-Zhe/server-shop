## 1. 新增了什么

| 入口 | 作用 |
| --- | --- |
| `/shop admin money <金额> [目标...]` | 发金币；不填目标 = 所有已知玩家（含离线） |
| `/shop admin send` | 打开发放界面（放物品 + 勾选玩家/全体 + 金额 → 发送） |
| 商店设置页 →「发放物品 / 金币」按钮 | 等同于 `/shop admin send` |
| 邮箱 | 新增「管理员发放」邮件文案（显示发放人与物品/金币） |

权限：与 `admin` 子命令一致，需要 **2 级 OP**；发放动作在服务端二次校验权限，客户端伪造操作包无效。

## 2. 发钱指令

```text
/shop admin money 1000                  # 所有已知玩家各 1000（在线 + 进过服的离线玩家）
/shop admin money 1000 示例玩家 Steve     # 指定玩家，支持离线玩家名（按模组账户表匹配）
/shop admin money 500 all               # 等价写法：all / @a / *
/shop admin money 500 <UUID>            # 也可以直接写玩家 UUID
```

* **直接到账**：余额立刻增加；在线玩家收到「你获得了 X金币，当前余额 Y金币」提示 + 音效；离线玩家下次登录即可看到余额。
* 名字匹配顺序：在线玩家名 → 账户表里的历史玩家名（所以离线玩家能收到）→ 都不匹配则提示「找不到这些玩家：xxx」。
* **余额上限**：超过 `wallet.maxBalance` 的差额不再发放，回执会提示有几人已达上限。
* 回执示例：`已给 3 名玩家各发放 50 金币（其中离线 3 名）`。

## 3. 发放界面（`/shop admin send`）

```
┌ 物品槽 3×9（从背包放入要发的东西） ┐   ┌ 玩家列表（点击=勾选/取消）┐
│ 放入即从背包扣除，最多 27 格      │   │ 支持搜索、翻页、在线/离线标记 │
├ 金额输入框（可留空）              │   ├ 上一页 / 下一页             │
├ 全体玩家 / 全不选                 │   └ 【发送】                    │
└ 已选 x / y 名玩家 + 提示           └ 玩家背包（3 行 + 快捷栏）      ┘
```

1. 把要发放的物品从背包拖入物品槽（支持多格、多种物品、整组）。
2. 右侧点玩家行勾选（再点取消）；「全体玩家」一键全选，「全不选」清空。
3. 需要额外发钱就在「金额」里填数字（留空 = 只发物品）。
4. 点「发送」。

发送结果：

* **物品**：每个目标、每一格物品生成一封**物品邮件**，发送者显示管理员名字；玩家打开**邮箱**点「领取」后进背包（背包满按模组既有规则退回邮箱）。
* **金币**：按当前设置**直接到账**（与发钱指令一致）。想改成"进邮箱领取"，把 `GrantManager.GRANT_MONEY_VIA_MAIL` 改成 `true` 重新编译。
* 管理员回执：`发放完成：N 名玩家（物品 3 种、金币各 1000）`。

## 4. 安全与边界（全部服务端权威）

1. 物品真实存放在**服务端容器槽位**里，客户端只提交「发给谁 / 发多少」，改客户端无法凭空造物品或造目标。
2. **关闭界面未发送**（含掉线）→ 槽内物品原样退还到管理员背包，放不下就掉在脚下，不会丢。
3. 点「发送」时**先清空槽位再关界面** → 不存在"既发出去又被退还"的刷物品路径。
4. 目标只接受服务端已知账户（在线玩家或账户表里的 UUID），客户端无法伪造目标。
5. 邮箱满：物品走模组既有兜底（在线优先塞背包，塞不下掉落并提示；离线仍保留在邮箱）；金额类邮件满则直接到账。
6. 所有变更都在 `ShopManager.LOCK` 内完成并 `setDirty()` 存档。

## 5. 构建与部署

```powershell
cd <工程目录>
.\gradlew.bat build
# 产物：build\libs\server_shop_mod-1.13.0.jar
```

> ⚠️ **构建时必须按 UTF-8 处理资源模板**（已在 `build.gradle` 里修好）：
> 模板 `src\main\templates\META-INF\neoforge.mods.toml` 里有 `displayName="服务器商店"`。
> 在默认编码是 GBK 的 Windows 上，`generateModMetadata` 会把中文写成**非法 UTF-8 字节**，
> FML 解析时抛 `MalformedInputException`，直接报 `...is not a valid mod file`，**服务端根本起不来**。
> 现已加 `tasks.withType(ProcessResources) { filteringCharset = 'UTF-8' }` + `org.gradle.jvmargs=... -Dfile.encoding=UTF-8`，
> 若以后换构建机/换构建脚本，请保留这两处设置。

* **已部署到服务端**：`<服务端目录>\mods\[服务器商店]server_shop_mod-1.13.0.jar`
  （文件名与版本号保持 1.13.0，直接覆盖旧文件，不会出现"两个同 modId"的启动报错）
* **原版备份**：`上游原版备份（本地保留，不随仓库发布）`
  （SHA-256 `206dc887bea31d840f05c0283df22a9604201663ed1902277c3bafb1998c810d` = 你发来的那一份，要回滚直接覆盖）
* ⚠️ **客户端也要放同一个 jar**：商店界面（含新的发放界面）是客户端代码。
  当前 `God Pussy1.0.3` 客户端实例的 `mods\` 里**没有**这个模组，请把同一个 jar 放进能连到你服务器的那台客户端的 `mods\`。
  客户端没装/旧版时，`admin_grant` 数据包会被忽略（表现为界面打不开），不会崩服。

## 8. 已知限制

1. 邮件模型是「一封邮件一个 ItemStack」：一次发 27 格 × N 人 = N×27 封邮件，容易占满邮箱（默认 50 封/人）。发大量物品建议少量多次。
2. 「全体玩家」= 模组账户表里的所有玩家（含离线），**不含**从未来过服务器的玩家。
3. 界面里勾选目标不会随玩家上下线实时增删（点开发送界面时的快照）；重开界面即可刷新。
4. 金额直接到账时不会给离线玩家留言，他们下次登录只会在余额里看到变化。
5. 服务器 `server.properties` 目前是 `enable-rcon=true` + 密码 `<RCON_PASSWORD>`（之前联调留下的），公网服请改回 `false`。
