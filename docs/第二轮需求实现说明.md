## 1. 金币封顶不再“凭空销毁”（按上一轮报告的建议方案）

统一原则：**要么全额到账，要么把装不下的部分留在凭据里**，绝不静默截断。

| 位置 | 现在的行为 |
| --- | --- |
| 邮箱里的金额邮件（单个领取 / 一键领取） | 只领取余额装得下的部分，**剩余金额留在邮件里**（邮件不标记已查看），有空间再领 |
| 拍卖被超价退款 | 先饱和入账，装不下的部分**自动改发一封金额邮件**（新增来源 `auction_refund`，邮箱里有对应文案） |
| 玩家间转账 `/pay` | 对方余额装不下**整笔拒绝**（避免付款方已扣、收款方只收到一部分） |
| 玩家交易里的金币 | 任一方余额装不下就**不执行交换**并提示，双方确认状态复位 |
| 邮箱满时的系统入账 | 先尽量直接到账，余额也装不下的部分**留在邮箱（超上限）**，不销毁 |
| 收购(`sellBuyback`)/发放 | 上一轮已改为“先算剩余空间再收物品/发放” |

新增统一工具 `ShopManager.credit(account, amount, max)`：饱和加法（先算剩余空间再取小），
既不会溢出成负数，也不会超过 `maxBalance`。

## 1.5 拍卖：出价即扣款、被超价即退回（本轮补齐了反馈与兜底）

### 现状：这两条本来就已实现（已逐行核对）

* **出价即扣款**：`placeBid` 通过校验（不是卖家本人、≥起拍价或当前价+加价幅度、余额足够）后立刻
  `bidder.balance -= amount`，并把 `topBidder` 改成出价者。
* **被超价即退回**：新出价落地的同时，上一位最高出价者通过 `credit()` **立刻退回原出价**——
  进余额；只有当他的余额恰好被顶到上限装不下时，差额才自动改发一封金额邮件（来源 `auction_refund`）。
* `data.auctions` 只有「创建」和「到期结算」两处改动，**不存在"拍卖被下架/移除"的旁路**，
  所以没有"拍卖没了但钱没退"的路径。
* 到期结算：有人出价 → 买家收物品邮件、卖家收货款邮件（扣手续费）；无人出价（流拍）→ 物品原样退回卖家，不扣任何人的钱。

### 本轮补的 4 个缺口（都是"看起来钱没退"的来源）

1. **被超价的提示 + 余额刷新**：提示改为「你在 X 的拍卖中被超价，旧价 Y金币 **已退回余额/邮箱**，新价 Z金币」，
   并立即给被超价玩家推一次静默快照——以前他的界面余额还停在冻结时的数字，看起来就像没退。
2. **拍卖列表显示最高出价者**：新增 `topMe` 字段，每行右侧显示「最高：xxx」，自己保持最高时显示金色「最高：你」，
   一眼确认钱还在冻结中；**自己的拍卖不再提供"出价"入口**（原来点进去填完金额才被服务端拒绝）。
3. **出价界面写明规则**：新增「出价即从余额扣款，被超价/流拍自动退回」+「当前余额 X」两行；
   并每次渲染都用最新快照刷新当前价与最低出价（别人加价后不会再按旧提示出价被拒）；拍卖已结束时显示「该拍卖已结束」。
4. **兜底退款**：若存档里的拍卖物品解析失败（例如物品所属模组被移除）导致无法成交，
   现在会把买家的出价**原额退回**（超上限部分转金额邮件），杜绝"付了钱没拿到货"。

## 2. 交易中断 → 物品按情况退回（背包优先，其次邮箱）
新增配置 `trade.tradeSessionTimeoutSeconds`（默认 **600 秒**）：

* 双方**同意后**的交易，只要超过 10 分钟没有任何操作（加物品/改金额/同意/确认都算操作），
  服务端自动结束会话，并按下面的规则退回双方放进去的物品：
  * **在线**：先回背包；背包放不下 → 进邮箱；邮箱满 → 掉在脚下（沿用 `addItemOrMail` 的兜底）；
  * **离线**：直接进邮箱（下次登录领取）。
* 触发场景覆盖“界面被顶掉”（死亡、切界面、客户端崩溃）：以前会话会一直挂在内存里、物品被冻结，
  只能等掉线或停机；现在最多 10 分钟自动退回，双方还会收到
  “交易长时间无操作已自动结束，物品/金币已退回（背包放不下的进邮箱）”的提示。
* 主动取消（按 ESC / 取消按钮 / 掉线 / 停机）的退回行为不变。

## 3. 同 IP 多账号管控

### 3.1 你服务器上的 AuthMe 其实已经配好了

`plugins/AuthMe/config.yml`：

```yaml
maxRegPerIp: 1      # 第 145 行：同一个 IP 只能注册 1 个账号（0=不限）——已经是你要的效果
maxLoginPerIp: 0    # 第 210 行：同一 IP 允许同时在线的人数（0=不限）
```

* `maxRegPerIp: 1` 拦住的是「同一个 IP 注册第二个账号」。
* 想让**同一 IP 不能同时在线两个号**，把 `maxLoginPerIp` 改成 `1` 即可（注意：同一家庭/网吧共享出口 IP 时会互相顶号）。
* AuthMe 管不到的情况：两个号在**不同 IP** 分别注册，之后又在**同一 IP** 轮流登录；用 VPN/手机流量换 IP 注册。

### 3.2 模组侧新增的“IP ↔ 账号”绑定（补上上面那个缺口）

* 配置（`config/server_shop_mod_1789689358-common.toml`）：
  ```toml
  [anti_alt]
  ipAccountLimit = 1        # 1 = 同一个 IP 只允许一个账号登录；0 = 关闭
  ipLimitExemptOps = true   # 2 级权限管理员豁免（方便多开测试）
  ```
* 第一次见到某个 IP 就把当前账号绑定上去；之后同一个 IP 用**别的账号**登录会被踢下线，并提示
  「该 IP 已绑定账号 XXX，同一个 IP 只能使用一个账号」。
* 绑定关系持久化在模组存档里（`ipOwner`），重启不丢。
* 管理命令：
  ```text
  /shop admin ip list                    # 查看所有 IP → 账号 绑定
  /shop admin ip unbind <玩家名>          # 解除该玩家的 IP 绑定
  /shop admin ip unbind <IP>             # 按 IP 解除（换宽带/共享 IP 误伤时用）
  ```
* ⚠️ **副作用要提前知道**：动态 IP（宽带重播号）可能把 IP 换给别的玩家，导致误伤；
  共享宽带（一家多台电脑）会互相顶号。所以：
  * 管理员默认豁免（`ipLimitExemptOps=true`），你自己的号不会被拦；
  * 一旦有正常玩家被误伤，用 `/shop admin ip unbind <玩家名>` 立刻解绑；
  * 不想要这层管控就把 `ipAccountLimit` 改成 `0`（AuthMe 那层仍然生效）。

* 上限 100 封 = 最多 3 页。

## 7. 管理员查看某个玩家的交易记录

### 7.1 新指令（控制台 / RCON 也能用）

```text
/shop admin history <玩家名>          # 第 1 页
/shop admin history <玩家名> 2        # 第 2 页（每页 8 条，最新在最上面）
```

输出示例（实测）：

```
示例玩家 transaction history (page 1/1, 1 entries, balance 919)
[09-26 10:31] Admin grant (coins) 管理员 +50 balance 919
```

### 7.2 界面入口

「商店设置」页多了个 **「交易记录」** 按钮（在「发放物品 / 金币」右边）：点一下弹出输入框，
填玩家名 → 回车 → 流水直接打到聊天栏（等价于 `/shop admin history <玩家名>`）。

### 7.3 记录范围与存储

会记流水的事件：商店购买/出售、摊位买/卖、拍卖出价/被超价退款/得标/成交、玩家间转账（双方）、
玩家交易（双方）、邮箱领取物品/金币、管理员发钱/发物品。

* 每条只存**文本摘要**：时间、类型、对方、金币变动、变动后余额、物品说明（如 `钻石×64`），
  **不存 ItemStack**，所以不会把存档撑大；
* 每名玩家最多保留 `mailbox.transactionHistorySize` 条（默认 **50**，范围 10..200），超出丢最旧的；
* 玩家名支持在线名、离线历史名和 UUID。
