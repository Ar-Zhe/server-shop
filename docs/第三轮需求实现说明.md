## 1. 修改条目后不再跳回第一页

**根因**：服务端每次处理完动作（改价格/品质/数量、购买、领取…）都会下发一份新快照；
客户端此时当前界面是「输入弹窗」而不是商店界面，于是会**重建一个新的 ShopScreen**，
本地保存的 `adminPage`（以及拍卖/邮箱页码、当前页签、编辑模块）全部归零 → 被弹回第一页。

**做法**：把界面状态提升到客户端缓存 `ClientShopData`，重建界面时自动还原：

* 新增 `lastTab / lastAuctionPage / lastAdminPage / lastMailPage / lastAdminMode`；
* `ShopScreen.tick()` 每秒把这些值同步进缓存，`init()` 时还原；
* 服务端没指定页签时（`defaultTab` 为空）用上次的页签兜底。

这样管理员改完一条会**停在原来的页和原来的「每日商店/每日收购」模块**上，拍卖/邮箱翻页同理不再回弹。
（切换页签仍会重置到第 1 页，这是预期行为；切换编辑模块会重置页码，因为条目数变了。）

## 4. 每日商店“普通”档位最多 3 个

* 生成逻辑改为：先剔除已经满额的品质，再按权重抽取；普通档默认最多出现 **3** 个。
* 新配置：`daily_shop.dailyShopCommonLimit`（默认 **3**，范围 0..6，**0 = 不限制**）。
* 其它档位不受影响；每个物品仍然只出现一次（原有去重逻辑不变）。

## 5. 付费刷新每日商店

* 位置：每日商店页右下角一枚**小按钮**（52×12），文字「刷新」；鼠标悬停显示提示：
  * 可用时：「刷新每日商店：200金币（今日剩余 2/2 次）」
  * 用完时（按钮变灰）：「今日刷新次数已用完（共 2 次）」
* 价格与次数来自配置：`daily_shop.dailyRefreshCosts = ["200", "500"]` —— 按顺序取用：
  第 1 次 **200**，第 2 次 **500**；想加第 3 次就往后追加一条（如 `"1000"`），删掉即减少次数。
* 每次刷新：扣费 → 重新生成整页卡片（含翻牌状态重置）→ 价格按当前商品池刷新 → 全量快照回传；
  聊天栏回执「已刷新每日商店，花费 200金币（下次刷新 500金币）」。
* 次数与余额都由服务端校验（改客户端无效）；**每天 0 点随每日商店一起重置**。
* 记录进交易流水（类型「刷新每日商店」），管理员可用 `/shop admin history <玩家>` 查。

## 6. 收购清单全部完成奖励 1000 金币

* 规则：把当日收购清单里**每一项都卖满**后，一次性奖励 **1000 金币**（每天一次）。
* 配置：`daily_buyback.buybackAllBonus`（默认 **1000**，0 = 关闭）。
* 界面：每日收购页底部显示进度：
  * 未完成：「全部完成可额外奖励 1000金币（还剩 N 项）」
  * 已完成：「今日收购已全部完成，奖励 1000金币 已发放」
* 发放时聊天栏提示「今日收购清单全部完成！额外奖励 1000金币」，并写入交易流水（类型「收购全清奖励」）。
* 边界：空清单不会白送（`dailyBuyback` 为空时直接跳过）；奖励受 `maxBalance` 上限约束（用饱和入账，不会溢出/负数）。
